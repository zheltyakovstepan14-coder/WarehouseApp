# Безопасность и риски

## Реализованные меры
- Аутентификация через JWT (`authToken` + middleware `authenticate`).
- Разграничение доступа на уровне UI/операций (RBAC).
- Серверная валидация и проверки бизнес-условий в маршрутах.
- Хэширование паролей (`bcrypt`).

## Ключевые риски и меры снижения

### 1. Несанкционированный доступ
- Риск: попытка выполнения действий без роли.
- Контроль:
  - проверка токена на сервере;
  - проверка прав на клиенте и сервере;
  - сокрытие недоступных действий в UI.

### 2. Нецелостность данных остатков
- Риск: рассинхронизация статусов/количества при параллельных операциях.
- Контроль:
  - единый API-контракт;
  - атомарные обновления в БД;
  - повторная синхронизация статусов после критичных операций.

### 3. Регрессии при рефакторинге
- Риск: сломанные потоки после изменений фронтенда.
- Контроль:
  - e2e-smoke (5 критичных сценариев);
  - пошаговый модульный вынос с обратной совместимостью (`window`-адаптеры).

### 4. Ошибки пользовательского ввода
- Риск: неверные даты/количества/статусы.
- Контроль:
  - client-side валидация;
  - server-side валидация;
  - предсказуемые сообщения об ошибках.

## Рекомендации для production-уровня
- Добавить аудит-лог: кто/когда/что изменил.
- Добавить rate limiting на login и критичные write-endpoints.
- Добавить централизованный обработчик ошибок и классификацию инцидентов.
- Вынести секреты в `.env` + регламент ротации.

# Use Cases (для пояснительной записки)

## Роли
- Администратор
- Сотрудник склада
- Ответственный за аренду/мероприятия
- Руководитель (согласование закупок)

## UC-01: Создание аренды и проведение
- Актор: Ответственный за аренду.
- Предусловия: пользователь авторизован; объект есть в наличии.
- Основной поток:
  1. Открыть вкладку `Аренда`.
  2. Создать черновик, добавить позиции.
  3. Проверить статусы и доступность.
  4. Провести документ.
- Результат: аренда в корректном статусе, остатки синхронизированы.

## UC-02: Создание мероприятия и проведение
- Актор: Ответственный за мероприятия.
- Предусловия: пользователь авторизован; доступны объекты.
- Основной поток: аналогично UC-01 для сущности `Мероприятие`.
- Результат: документ проведен, движения отражены в системе.

## UC-03: Формирование закупочной заявки при дефиците
- Актор: Сотрудник склада.
- Предусловия: обнаружен дефицит/нулевой остаток.
- Основной поток:
  1. Открыть `Заявки на закупку`.
  2. Обновить/сформировать черновик.
  3. Проверить позиции и отправить на согласование.
- Результат: заявка создана, статус сохранен в БД.

## UC-04: Работа с документами (единый хаб)
- Актор: Сотрудник склада / Администратор.
- Предусловия: есть документы в реестре.
- Основной поток:
  1. Открыть `Документы`.
  2. Отфильтровать по типу/дате/основанию.
  3. Открыть карточку, выполнить разрешенное действие (провести/отменить/PDF).
- Результат: статус документа изменен и отображен в таблице.

## UC-05: Управление пользователями и правами
- Актор: Администратор.
- Предусловия: вход под ролью администратора.
- Основной поток:
  1. Открыть `Пользователи`.
  2. Создать пользователя/изменить активность.
  3. Назначить права и проверить доступы.
- Результат: политика доступа обновлена и применяется в интерфейсе.

## Негативные сценарии (минимум для защиты)
- Проведение документа при некорректном статусе объекта.
- Попытка доступа к вкладке без прав.
- Пустой/некорректный фильтр дат.
- Отсутствие данных для документа (обработка без падения).
